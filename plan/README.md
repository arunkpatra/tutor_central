# Tutor Central: build plan

A native iPhone app for tutors running a small tuition centre (`docs/spec.md`). One file per phase. Phases are
worked in order, except that Phase 1 runs beside Phase 0 (D6); each one ends with something to show.

## How to resume in a new session

Read `STATE.md` (where the work stands), then `SESSIONS.md` (how a session starts, works and ends), then the
phase file of the slice in hand. Resume prompts, when the owner asks for one, are in `resume/`.

Always:
1. Read `docs/reference/functional-inventory.md` before touching a feature: it is the contract for "nothing
   from the reference app is lost".
2. Read `docs/design/README.md` before any UI work. No board, no approval, no code.
3. When a phase changes status, set it here, in its own file and in `STATE.md`.

A phase starts with its plan file (`phase-NN-plan.md`: tasks, order, tests first, PR boundaries), written and
shown before any work. A phase ends with "As built" in its scope file: what exists, what deviated and why.

## Decisions

Numbered, dated, never reopened without a new number that supersedes the old.

| # | Date | Decision |
|---|---|---|
| D1 | 2026-10-07 | iOS 26 is the minimum. iPhone only in this build; iPad is a later phase. |
| D2 | 2026-10-07 | India first: rupees, UPI id and QR, WhatsApp numbers with +91 default. Currency is a column on the centre so other markets can follow. |
| D3 | 2026-10-07 | Parent messages (reminders, receipts, absence alerts, progress notes) open WhatsApp with a prefilled message through a deep link. Server-sent messages are a later phase. Every opened link is logged. |
| D4 | 2026-10-07 | Subscriptions, plans, student limits, message quotas and paywalls are deferred entirely. No limits anywhere in the product or the model. |
| D5 | 2026-10-07 | Stack: the app talks to Supabase directly (Auth, Postgres with RLS, Storage) through `supabase-swift`. A thin Hono API on Vercel exists only for AI and scanning. Multi-row operations are Postgres functions. |
| D6 | 2026-10-07 | Phase 1 (foundation) runs beside Phase 0 (design). Nothing user-facing is built without an approved board; plumbing may. |
| D7 | 2026-10-07 | Every pull request that changes what is seen carries simulator screenshots of each changed screen and state in its description, taken by a script and kept on the orphan branch `pr-shots`. None is merged without. |
| D8 | 2026-10-07 | Swift 6 strict concurrency, SwiftUI only, Observation. UIKit only behind a wrapper where SwiftUI cannot do the job, with the reason in the file. |
| D9 | 2026-10-07 | The Xcode project is generated by XcodeGen from `ios/project.yml`. The `.xcodeproj` is not committed. |
| D10 | 2026-10-07 | Style only through design tokens. No raw colour, size, radius, shadow or duration in a view. A missing value becomes a token first. |
| D11 | 2026-10-07 | AI runs through our API with Claude. No AI key in the app. Structured outputs, every generation recorded. |
| D12 | 2026-10-07 | A change to documents only (`plan/`, `docs/`, `README.md`, `CLAUDE.md` files) is committed and pushed to `main` directly, without a pull request. Never mixed with code. |
| D13 | 2026-10-07 | Both appearances are designed and built; dark is the hero. |
| D14 | 2026-10-07 | Dependencies are pinned exactly. `supabase-swift` is the only iOS dependency until a decision adds another. |
| D15 | 2026-10-07 | Tests: Swift Testing for Domain and Data, API tests with Bun, RLS tests against local Supabase, one launch smoke test. No UI test suites at this stage; screens are checked by hand in the simulator with screenshots (D7). |
| D16 | 2026-10-07 | Bun only on the TypeScript side. Never npm, npx, yarn or pnpm, in scripts or docs. |
| D17 | 2026-10-07 | Planning, scoping and design are done with Claude Fable 5.1; implementation moves to Claude Opus 5.5 once scope, approach and design are stable. The process in `SESSIONS.md` does not depend on which model runs. |
| D18 | 2026-10-07 | No ads, no tracking SDK, no App Tracking Transparency prompt, no third-party analytics. Crash reporting is a later decision. |
| D19 | 2026-10-07 | Working name Tutor Central; bundle id `app.journium.tutorcentral`. The final brand name and icon come in Phase 0 and do not block any phase. |
